        Common questions
        
          
        Which branch should I start from?
        For a new task, normally check GitHub, switch to main, receive its updates, then create a working branch. Creating here uses the current checkout, not automatically the newest main.
        
          
        What happens to unsaved or uncommitted work?
        Save your editor drafts first. Switching requires all saved changes to be checkpointed. Creating a branch on main can carry saved changes safely onto it; creating from a dirty working branch is blocked. Nothing is automatically discarded or stashed.
        
          
        What is a server branch? Does switching send anything?
        Server choices come from the last GitHub check. Check GitHub first if a branch is missing. Choosing a known server branch creates or selects its local checkout. Switching never pushes your work, merges into main or deploys the site.
        
          
        Why can I not edit main?
        Main is protected. Create or select a working branch to edit. After saving and checkpointing your changes, send that working branch to GitHub explicitly.
        
                
        
        Review Git operation
        What replaying your work means
        Illustration only — not a predicted result. Conflicts can pause the operation. Git confirms the actual history afterwards.
        Review the branch and operation before confirming. No automatic stash, merge or discard. Rewritten publication uses only an explicitly confirmed, exact force-with-lease, never an unconditional force.

        How it fits together
        A simple workflow
        This workspace combines the existing tools and a file-backed content studio. It does not configure production credentials or deploy the site.
        
        
        Start with Git & workspace
        Fetch to check the server, update a clean main checkout, then create or choose a working branch. The header always names your branch; editing stays locked on main. Saves change local files only. Review and select changed files to create a local checkpoint, then separately confirm sending your working branch to GitHub. Pull updates use rebase, not merge. To follow origin/main with a published branch, explicitly allow the backed-up rebase, then separately publish it with the exact force-with-lease. Concurrent server changes block publication; never override that rejection. The server map is last-known until you fetch again. Before switching branches, save your open editor drafts or use the dashboard to download and explicitly discard them. Conflicts offer text review, continue and abort; ask the maintainer if uncertain.
        
        
        Clean up loose portraits
        In Members & portraits, expand Roster & image checks. Select loose portrait files individually or with Select all, then Review & delete selected. Referenced files are blocked and show where they are used. Only checked files are permanently removed after confirmation. Check unsaved article drafts yourself before deleting. Untracked files cannot be restored with Git. Deleting a member still preserves their image files; cleanup is a separate action.
        
        
        1. Prepare the photos
        Use Site photos for article, gallery and hero photos. Set the output folder under static/images/. Existing files are preserved; duplicate names get a numeric suffix. Copy the resulting /images/... URL where needed.
        2. Manage members & portraits
        Select a member or Add member, edit their details and group, and choose an existing portrait pair or upload a photo below. Choose each face crop, inspect the circular preview and convert. Conversion fills the open member draft; Save member writes its details and image assignments together. Exported files remain even if you discard the draft. Delete member removes only the roster entry; historical report names and image files remain. Review Roster & image checks for missing images, unmatched names and unassigned portraits. Guests and files used elsewhere are not automatically errors. If an external edit causes a conflict, copy your draft before Reload. Skipping a photo never writes output. The crop uses original EXIF-corrected coordinates, not the smaller browser preview.
        3. Compose the hero
        Use the connected Hero slideshow editor for subject points, motion and per-device composition. Save explicitly. Remove takes an image out of the slideshow without deleting its file. Refresh the actual site preview to inspect the result.
        4. Check a shared link
        Paste a local or public URL into Social previews. Images and metadata come from the served HTML, not guesses. Export embeds images into an HTML snapshot you can share. Platform caches and cropping can differ.
        5. Verify before publishing
        Run Build & checks. Logs report errors rather than pretending success. There is no production deploy button here; use the existing reviewed deployment workflow.
        Local and explicit
        The server listens only on your machine. Uploaded originals are temporary and are removed on shutdown. Converted images, saved members and hero configuration persist in this checkout. Restarting loses queued originals, not exported images. Changes are not automatically committed.
        Setup
        Run scripts/setup-dev-env.ps1 once, then double-click site_editor.bat in the repository root. Stop the workbench with Ctrl+C in its terminal. The workbench replaces the separate image converters and hero-editor launcher.
